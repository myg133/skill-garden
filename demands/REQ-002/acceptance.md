# 验收标准：Tenant-Org-User 加入流程优化

## Phase 1.1: 组员搜索添加

### AC-001: 用户搜索功能
- **前置条件**: 系统中存在多个用户
- **测试步骤**: 
  1. 进入组织详情页 → Groups Tab → 点击某个组
  2. 在「添加成员」输入框输入搜索关键词（如 "张"）
  3. 等待 300ms 观察下拉结果
- **预期结果**: 
  - 显示匹配的用户列表（名字/邮箱包含关键词）
  - 响应时间 < 500ms
  - 点击用户后自动填入选中项
- **类型**: 功能

### AC-002: 添加成员成功
- **前置条件**: 
  - 当前用户是 org admin
  - 目标用户已在系统中存在
- **测试步骤**:
  1. 搜索找到目标用户
  2. 选择角色（如 member）
  3. 点击「添加」按钮
- **预期结果**:
  - 组成员列表更新，新成员出现在列表中
  - 显示成功 Toast 提示
  - 新成员的角色显示正确
- **类型**: 功能

### AC-003: 保留 UUID 输入方式
- **前置条件**: 当前用户是 org admin
- **测试步骤**:
  1. 展开「或输入 Identity ID」区域
  2. 输入已存在用户的 UUID
  3. 点击添加
- **预期结果**: 与搜索方式一样成功添加成员
- **类型**: 功能

## Phase 1.2: 加入申请流程

### AC-004: 用户提交加入申请
- **前置条件**: 
  - 组织 `join_policy` 为 `approval_required`
  - 用户未加入该组织
- **测试步骤**:
  1. 进入组织详情页
  2. 切换到「申请加入」Tab
  3. （可选）填写申请留言
  4. 点击「提交申请」
- **预期结果**:
  - 申请提交成功
  - 显示「申请已提交，等待审批」
  - 页面显示申请状态为 pending
- **类型**: 功能

### AC-005: 管理员查看待审批申请
- **前置条件**: 存在 pending 状态的申请
- **测试步骤**:
  1. 以 org admin 身份登录
  2. 进入组织详情页
  3. 切换到「管理申请」Tab
- **预期结果**:
  - 显示所有 pending 状态的申请
  - 每条申请显示：申请人信息、申请时间、留言内容
- **类型**: 功能

### AC-006: 管理员批准申请
- **前置条件**: 存在 pending 状态的申请
- **测试步骤**:
  1. 在「管理申请」Tab 中找到待审批申请
  2. 点击「批准」按钮
  3. 确认操作
- **预期结果**:
  - 申请状态变更为 approved
  - 申请人在组织成员列表中出现
  - 申请人的角色正确（默认 member）
- **类型**: 功能

### AC-007: 管理员拒绝申请
- **前置条件**: 存在 pending 状态的申请
- **测试步骤**:
  1. 在「管理申请」Tab 中找到待审批申请
  2. 点击「拒绝」按钮
  3. 确认操作
- **预期结果**:
  - 申请状态变更为 rejected
  - 申请人不在组织成员列表中
- **类型**: 功能

### AC-008: 重复申请校验
- **前置条件**: 用户已有 pending 状态的申请
- **测试步骤**:
  1. 再次进入同一组织的「申请加入」Tab
  2. 尝试提交新申请
- **预期结果**:
  - 显示错误提示「已有待处理的申请」
  - 不能重复提交
- **类型**: 功能

### AC-009: 已加入组织用户不显示申请入口
- **前置条件**: 用户已是组织成员
- **测试步骤**:
  1. 以组织成员身份登录
  2. 进入该组织详情页
- **预期结果**:
  - 不显示「申请加入」Tab
  - 只显示「Members」Tab
- **类型**: 功能

### AC-010: 非管理员不能审批
- **前置条件**: 用户是组织成员但非 admin
- **测试步骤**:
  1. 进入组织详情页
- **预期结果**:
  - 不显示「管理申请」Tab
- **类型**: 安全

## Phase 1.3: 组织层级可视化

### AC-011: 租户详情页显示关联组织
- **前置条件**: 租户下有多个组织
- **测试步骤**:
  1. 进入租户列表页
  2. 点击某个租户进入详情页
- **预期结果**:
  - 显示「关联组织」区块
  - 列出该租户下的所有组织
  - 每个组织显示名称、成员数
  - 支持点击跳转到组织详情
- **类型**: 功能

### AC-012: 租户详情页显示管理员列表
- **前置条件**: 租户有多个管理员
- **测试步骤**:
  1. 进入租户详情页
- **预期结果**:
  - 显示「租户管理员」区块
  - 列出所有 tenant_admin 角色用户
- **类型**: 功能

### AC-013: 组织详情页显示所属租户
- **前置条件**: 组织属于某个租户
- **测试步骤**:
  1. 进入组织详情页
- **预期结果**:
  - 侧边栏或页面顶部显示「所属租户: xxx」
  - 支持点击跳转到租户详情页
- **类型**: 功能

## 边界条件测试

### BC-001: 搜索无结果
- **前置条件**: 搜索关键词无匹配用户
- **测试步骤**: 输入一个不存在的用户名
- **预期结果**: 显示「未找到匹配用户」提示
- **类型**: 边界

### BC-002: 用户被禁用后不能申请
- **前置条件**: 用户状态为 suspended
- **测试步骤**: 尝试申请加入组织
- **预期结果**: 
  - 前端不显示申请入口
  - 或后端返回 403 Forbidden
- **类型**: 安全

### BC-003: 组织删除后申请自动失效
- **前置条件**: 存在 pending 申请，组织即将被删除
- **测试步骤**: 删除组织
- **预期结果**: 
  - 该组织的所有申请一并删除
  - 或申请状态变更为 invalid
- **类型**: 数据一致性

### BC-004: 审批人不能是自己
- **前置条件**: A 申请加入某组织
- **测试步骤**: A 同时是 org admin，试图审批自己的申请
- **预期结果**: 
  - A 在「管理申请」中看不到自己的申请
  - 或后端禁止自我审批
- **类型**: 安全

## 性能测试

### PT-001: 搜索性能
- **测试方法**: 在 1000 个用户中搜索
- **预期结果**: 响应时间 < 200ms
- **类型**: 性能

### PT-002: 申请列表加载性能
- **测试方法**: 查看有 100 个待审批申请的组织
- **预期结果**: 
  - 页面加载 < 1s
  - 支持分页（每页 20 条）
- **类型**: 性能
