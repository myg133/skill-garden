## 调度原则

1. **先来先服务**：按需求进入"已就绪"队列的顺序分配
2. **技能匹配**：根据需求类型（API/前端/后端/安全）匹配合适 Agent
3. **并行度控制**：单个 Agent 同时最多持有 2 个需求
4. **优先级抢占**：P0 需求可打断 P1/P2 的进行中任务

## 需求优先级定义

| 优先级 | 定义 | 响应 SLA |
|--------|------|----------|
| P0 | 核心功能阻塞 / 安全漏洞 | 立即处理 |
| P1 | 重要功能缺失 / 严重 Bug | 24h |
| P2 | 功能改进 / 一般 Bug | 1 sprint |
| P3 | 优化 / 体验提升 | 排期决定 |

## Dev Agent 分配流程

```
需求状态 = "已就绪"
  → 检查可用 Agent（registry.md 中 status = "idle"）
  → 按技能标签匹配
  → 创建 feature-REQ-xxx/ worktree
  → 更新 registry.md
  → 更新需求 status.md → "进行中"
```
